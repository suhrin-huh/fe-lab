# 함수형 프로그래밍에 대해서 설명해주세요.

**핵심 키워드** : `함수형 프로그래밍`, `순수 함수`, `불변성`, `고차 함수`

## `함수형 프로그래밍(functional programming)`

사용자 인터페이스는 상태(state)와 이벤트(event)의 흐름 위에 구축된 구조이다. 이벤트가 발생하면 상태가 바뀌고, 그에 따라 화면이 다시 그려지며, 또 다른 인터렉션이 이어진다. 이처럼 변화무쌍한 상호작용을 예측 가능하고 안정적으로 다루는 것은 프론트엔드 개발의 매우 핵심적인 과제이다.

함수형 프로그래밍(functional programming)이란 상태를 변경하지 않고, 부작용을 최소화하며, 함수를 일급 객체로 다루는 방식이다. 컴퓨터 과학의 오래된 이론인 `람다 계산법(Lamba Calculus)`에서 출발한 개념으로, 비교적 최근에서야 프론트엔드 개발자들 사이에서 널리 쓰이기 시작한 패러다임이다. 전통적인 프로그래밍이 "컴퓨터가 어떤 순서로 어떤 일을 할 것인가"에 초점을 둔다면, 함수형 프로그래밍은 `무엇을 계산할 것인가`에 집중한다. `어떻게(How)`가 아닌 `무엇을(What)`에 대한 기술인 것이다. 이는 곧 `선언형 프로그래밍(declarative programming)`과 맞닿아 있고, React같은 현대 프론트엔드 프레임워크가 함수형 프로그래밍에서 큰 영향을 받은 이유이기도 하다.

### 순수함수
함수형 프로그래밍의 중심에는 `순수 함수(pure function)`라는 개념이 있다. `순수 함수`란 <u>같은 입력이 주어졌을 때 항상 같은 결과를 반환하며, 외부 상태를 변경하지 않는 함수</u>다.

```js
// 순수 함수
function add(a,b) {
  return a+b;
}

// 순수하지 않은 함수
let num = 0;
function add() {
  num += 1; // 외부 상태를 변경
}

```

전통적인 명령형 프로그래밍은 상태(state)를 변경하면서 프로그램이 흐른다. 예를 들어 어떤 변수를 만들고 값을 바꾸는 방식이다. 이 과정에서 동일한 입력에도 불구하고 실행 시점이나 환경에 따라 결과가 달라질 수 있는 문제가 발생한다. 반면, 함수형 프로그래밍은 순수 함수를 강조하고, 상태 변경을 지양함으로써 이러한 예측 불가능성을 줄인다. 입력과 출력 사이의 관계만 보면 되므로, 부수 효과(side effect)가 적으며 코드의 예측 가능성과 안정성이 높아진다.

```js
// 비순수 함수
let total = 0;

function addToTotal(num) {
  total += num;
  return total;
}

addToTotal(5); // 5
addToTotal(5); // 10
addToTotal(5); // 15
// ...

// 함수의 실행이 많고 복잡해질수록 각 함수의 결과를 예측하기가 어려워진다.


// 순수 함수
function add(a, b) {
  return a + b;
}

add(5, 0);  // 5
add(5, 5);  // 10
add(5, 10); // 15

// 입력값만 보고도 결과를 완벽히 예측할 수 있다.

```

### 불변성(immutability)과 고차 함수(higher-order function)
함수형 프로그래밍은 또한 `불변성(immutability)`을 중요하게 여긴다. 데이터를 직접 바꾸는 것이 아닌, 기존 데이터를 기반으로 새로운 데이터를 생성하는 방식을 선호한다. 예를 들어 배열을 정렬할 때, 원본 배열을 바꾸는 대신 새로운 배열을 반환하는 방식이다. 이 원칙은 React에서 상태(state)를 업데이트할 때 setState를 사용하거나, Redux에서 reducer가 새로운 상태 객체를 반환하는 방식과도 연결된다. 이는 UI의 상태 변화가 예측 가능하도록 만들어주고, 버그 발생 가능성을 줄여준다.

이러한 원칙을 실현하기 위해 함수형 프로그래밍에서는 `고차 함수(higher-order function)`를 적극 활용한다. 고차 함수란 함수를 인자로 받거나, 함수를 반환하는 함수로, JS에서는 `map`, `filter`, `reduce` 같은 배열 메서드들이 대표적이다. 이 함수들은 상태를 직접 변경하지 않고, 새로운 배열을 생성한다.

> `일급 객체(first-class citizen)`
>
> JS에서는 함수형 프로그래밍의 특성을 비교적 자유롭게 적용할 수 있는데, 이는 함수를 `일급 객체`로 취급하기 때문이다. 즉, 함수가 변수에 저장될 수 있고, 다른 함수의 인자로 전달되거나 반환값으로 사용될 수 있다. 이 덕분에 `map`, `filter`, `reduce`과 같은 고차 함수를 사용해 데이터를 불변의 상태로 처리하는 방식이 가능해진다. 이는 React와 같은 UI 라이브러리에서도 매우 중요하게 작용한다.


```js
const numbers = [1,2,3,4,5,6];

// 원본의 변화없이 result 계산을 위한 배열 반환
const result = numbers.filter(n => n % 2 === 0).map(n -> n*2).reduce((acc, cur) => acc + cur, 0);

console.log(result) // 24
```

함수형 프로그래밍은 리액트 컴포넌트의 구조에도 깊숙이 영향을 주고 있다. 리액트의 함수형 컴포넌트는 클래스 없이 순수한 함수로 UI를 정의하며, 상태 관리에서도 다양한 라이브러리들이 함수형 사고방식을 기반으로 상태 흐름을 설계한다. 또한 RxJS처럼 비동기 이벤트 스트림을 함수로 조합하는 리액티브 프로그래밍도 함수형 패러다임을 따르고 있어, 함수형 사고를 잘 이해하면 복잡한 UI 상호작용과 상태 흐름도 보다 명확하게 설계할 수 있다.

---

결국 함수형 프로그래밍은 단지 문법이나 트렌드의 문제가 아닌, 복잡한 사용자 인터페이스를 안정적으로 구성하고 유지하기 위한 사고 방식이다. 코드의 예측 가능성과 재사용성을 극대화하고, 변화에 유연한 시스템을 만들기 위한 설계 철학이라 볼 수 있다. 그래서 프론트엔드 개발자라면 단순히 함수형 문법을 아는 것을 넘어, 그 철학과 개념이 실무의 어디에, 어떻게 적용되고 있는지 이해하는 것이 중요하다.
