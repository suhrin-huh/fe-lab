# 이벤트루프에 대해 설명해주세요.

## 자바스크립트의 비동기 처리와 이벤트 루프
자바스크립트는 본질적으로 싱글 스레드 기반의 언어로, 브라우저 환경에서 DOM 조작이나 UI 업데이트를 안전하고 예측 가능하게 수행하기 위해 한 번에 하나의 작업만 처리한다. `콜 스택(Call Stack)`은 함수 호출들을 순서대로 쌓고 관리하여 동기적인 코드의 흐름을 정확하게 유지하는 자료구조로, 함수가 호출되면 스택에 쌓이고 실행이 완료되면 제거되는 후입선출(LIFO) 방식이다. 이 구조 덕분에 자바스크립트는 함수 호출 순서를 정확하게 관리할 수 있다.

### 이벤트 루프의 등장과 역할
웹 환경에서는 네트워크 요청, 타이머, 사용자 입력 처리 등 시간이 오래 걸리거나 완료 시점을 예측하기 어려운 비동기 작업들이 필연적으로 발생한다. 이러한 작업들을 싱글 스레드인 콜 스택에서 동기적으로 처리할 경우, 작업이 끝날 때까지 스택이 블로킹되어 UI가 멈추게 된다. `이벤트 루프(Event Loop)`는 싱글 스레드의 한계를 극복하고 비동기 작업을 논블로킹 방식으로 효율적으로 처리하기 위해 등장한 메커니즘이다.

비동기 함수가 호출되면, 해당 작업은 콜 스택에서 바로 처리되지 않고 브라우저의 `Web API`나 `Node.js 환경의 백그라운드 스레드`로 위임된다. 백그라운드에서 작업이 완료되면, 그 결과로 실행될 콜백함수는 `테스크 큐(Task Queue)`라는 대기 공간으로 이동한다. `이벤트 루프`는 콜 스택이 완전히 비어 있는지를 지속적으로 감시하며, `콜 스택`이 비어 있는 바로 그 시점(= 모든 동기 코드가 실행 완료된 후)에 `테스크 큐`에 대기 중인 콜백 함수를 꺼내 `콜 스택`으로 밀어 넣어 실행한다. 이러한 순환 과정 덕분에 자바스크립트는 UI 렌더링을 멈추지 않고 비동기 작업을 처리할 수 있다.

### 예시


```js
function a() {
  console.log('a 실행');
  b();
}

function b() {
  console.log('b 실행');
}

a();
console.log('끝');
```

- 출력 순서 : `a → b → 끝 출력`
- 콜 스택에는 a가 먼저 쌓이고, 그 안에서 b가 쌓이며, 실행이 끝나면 하나씩 제거

```js
console.log('시작');

setTimeout(() => {
  console.log('타이머 완료');
}, 0);

console.log('끝');
```

- 출력 순서 : `시작 -> 끝 -> 타이머 완료`
`setTimeout` 콜백이 `0ms`로 설정되어 있어 즉시 실행될 것이라 생각할 수 있으나, 콜백은 바로 콜 스택에 들어가는 것이 아니라 `테스트 큐`에 들어가고, 콜스택이 비워진 뒤 이벤트 루프가 옮겨 실행!


## 테스트 큐의 우선순위 관리

`태스크 큐`는 `마이크로태스크(Microtask)`와 `매크로태스크(Macrotask)` 두 가지로 나뉘어 비동기 작업의 우선순위가 관리된다.

- `마이크로태스크 큐` : `Promise`의 `.then()`, `.catch()`, `.finally()` 콜백 등 중요도가 높은 작업들이 대기
- `매크로태스크 큐` : `setTimeout()`, `setInterval()`, I/O, UI 렌더링과 같은 일반적인 비동기 작업들이 대기

### 예시
```js
console.log('시작');

setTimeout(() => {
  console.log('매크로태스크');
}, 0);

Promise.resolve().then(() => {
  console.log('마이크로태스크');
});

console.log('끝');
```

- 출력 순서 : `시작 → 끝 → 마이크로태스크 → 매크로태스크`

> 실무에서 가장 중요한 건 큰 흐름!
>
> - 자바스크립트는 싱글 스레드
> - 콜 스택이 함수를 순차적으로 처리
> - 비동기 작업은 백그라운드(Web API)로 넘어가고, 완료되면 이벤트 루프가 스택으로 옮겨 실행
> - await, 프로미스, setTimeout 같은 비동기 패턴이 실행 순서에 영향을 준다
