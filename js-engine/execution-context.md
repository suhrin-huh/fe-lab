# 실행 컨텍스트에 대해 설명해주세요.

**핵심키워드** : `실행 컨텍스트`, ` 콜 스택``Variable Exvironment `, `Lexical Environment`

## 실행 컨텍스트

어떤 함수나 코드 블록이 실행될 때, 그 안에서 사용하는 변수, 파라미터, 스코프 정보 등 실행되기 위해 필요한 환경 정보들을 저장하는 실행 환경이 생성되며, 이를 흔히 `스택 프레임(stack frame)`이라고 부릅니다.
JS에서는 이러한 개념을 `실행 컨텍스트(execution context)`라고 부릅니다.

JS는 싱글 스레드 기반 언어로 코드가 순차적으로 실행되는데, 이를 관리하는게 `실행 컨텍스트 스택(Call Stack, Execution Stack)`입니다.

## 실행 컨텍스트의 생성

실행 컨텍스트는 크게 세 가지 상황에서 생성됩니다.

1. 자바스크립트는 프로그램이 시작되면 가장 먼저 `전역 실행 컨텍스트`가 콜스택에 추가됩니다. 이 컨텍스트는 프로그램이 종료될 때까지 계속 유지됩니다.
2. 이후 함수가 호출될 때마다 새로운 `함수 실행 컨텍스트`가 콜스택에 쌓이며, 함수 실행이 끝나면 해당 컨텍스트는 제거됩니다.

> `+` `eval` 함수가 사용될 때도 별도의 `eval 실행 컨텍스트`가 생성되지만, 일반적으로 사용을 권장하지 않습니다.

## 구성 요소

실행 컨텍스트는 다음과 같은 세 가지의 구성 요소로 이루어져 있습니다.

1. `Variable Exvironment`에는 `var`로 선언된 변수들과 함수 선언문이 저장되며 이 환경 안에서 값이 할당 및 변경됩니다.

2. `Lexical Environment`는 현재 실행중인 코드의 스코프 정보를 담고 있습니다. `let`, `const`로 선언된 변수들이 저장되며, 외부 스코프와 연결된 스코프 체인도 포함되어 있습니다.

> `Lexical` => 프로그래밍에서는 `코드가 작성된 위치`  
> 자바스크립트는 렉시컬 스코프를 사용하는 언어로, 함수나 변수는 어디서 작성되었는지에 따라 스코프가 결정됩니다. 이 렉시컬 정보를 기반으로 생성된 실행 환경이 `lexical environment`입니다.
> 즉, 실행 시점(runtime)이 아닌 작성 시점(compile)에 스코프가 결정된다는 것입니다.
>
> ```js
> let x = 1;
>
> function printX() {
>   console.log(x); // 렉시컬 환경에서는 x = 1
> }
>
> function wrapper() {
>   let x = 2; // 다이나믹 스코프일 때에는 x = 2
>   printX();
> }
>
> wrapper(); // 결과는 1
> ```

> <u>현재 실행중인 코드의 스코프 정보</u>란?
> 지금 실행 중인 코드가 어떤 변수들을 사용할 수 있는지에 대한 정보로, 각 변수가 정의된 위치와 탐색 방법에 대한 졍보가 포함되어 있습니다.

3. `this Binding`은 현재 컨텍스트에서 `this`가 어떤 객체를 가리키는지를 정의합니다.

## 동작 단계

1. `생성 단계(Creation Phase)`
   코드 실행 전에 실행 컨텍스트가 생성되어 변수와 함수 선언이 메모리에 등록되며 호이스팅이 발생합니다. `this`의 값이 결정되며, 스코프 체인이 생성됩니다.
2. `실행 단계(Execution Phase)`
   변수에 값이 실제로 할당되고, 함수가 호출되는 등의 코드 실행이 이루어집니다.

3. `소멸 단계 (Cleanup)`
   함수 실행이 끝나거나 전역 컨텍스트가 종료되면 실행 컨텍스트에서 제거됩니다. 가비지 컬렉터가 참조가 없는 메모리를 회수하며, 비동기 작업은 별도로 콜백 큐에서 다시 호출되어 새 실행 컨텍스트가 생성됩니다.
